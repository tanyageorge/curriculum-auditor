Curriculum Auditor

Find the prerequisites your course catalog gets wrong.

Muse Spark reads every prerequisite in a university catalog and maps it as a graph. Then code checks that graph for courses that require themselves, loops, and requirements on courses that no longer exist.

Open the app See a catalog with problems

Tested on 150 hand-labeled courses: 94.7% parsed exactly right, against 80.7% for a rule-based parser. 21,739 courses audited across 14 universities.

  1. Pick a university from the menu at the top of the app.
  2. Click a finding to see the catalog text it came from.
  3. Follow the graph: click any course in it to walk the chain.

    How well it works

    Every number on this page comes from a test run saved in the repository. The main accuracy number uses 150 courses I labeled by hand and scored only once, at the end.

    How it works

    The model reads the catalog, and my code checks the results. Anything that has to be exact, I do in code.

    1. Start with the catalog textI take each course's prerequisite text exactly as the university printed it.
    2. Muse Spark reads itMuse Spark 1.3 turns each sentence into AND/OR logic in a fixed JSON format: which courses, which ones are alternatives, which can be taken at the same time, and any minimum grade. If a sentence is unclear, it flags it instead of guessing.
    3. My code double-checks itEvery course Muse Spark lists has to actually appear in the text. If one doesn't, I send back the exact problem for one retry. If it still fails, the course is flagged for a person to review.
    4. A second opinionI also tried Muse Spark Open, the open-weights version, on Baseten to see if a second model would catch mistakes. It mostly made the same mistakes, so it didn't add much. I kept the result because it's worth knowing.
    5. Build the graph and check itMy code connects every course to its prerequisites and looks for problems: courses that require themselves, loops, required courses that don't exist, and courses that were renumbered.
    6. Write up the findingsEach finding is written by code, not by the model, so it always points to the exact catalog text it came from.

    Meta models I used

    • Muse Spark 1.3 on the Meta Model API reads every prerequisite.
    • Muse Spark Open (open weights, on Baseten) was my second-opinion test.

    Where the data comes from

    • 13 catalogs come from a public research dataset: Turaev et al., A Confound-Annotated Multi-Institution Curriculum Dataset with Parsed Prerequisite Logic (Mendeley Data, CC BY 4.0). For these I used the dataset's own parsed prerequisites, so any mistakes in it carry over.
    • The UIUC Spring 2026 catalog (Kaggle, from Wade Fagen-Ulmschneider's UIUC data, CC BY-SA 4.0) was parsed by Muse Spark for this project.
